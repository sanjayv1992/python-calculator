\chapter{Computational Verification and Results}\label{ch:results}

The theorems in Chapters~\ref{ch:primes}--\ref{ch:crypto} are proved by hand. This chapter reports numerical checks of the same statements, computed with the routines in Appendix~\ref{app:code}. The checks do not replace the proofs. They confirm that the statements and the algorithms agree on concrete inputs, and they catch arithmetic slips in the examples.

All values below were produced by running the code in \texttt{research-paper/code/}. The test suite (\texttt{python -m pytest research-paper/code}) passes with 312 test cases.

Table~\ref{tab:bezout} gives Bézout coefficients for several pairs. In every row, $ax+by=\gcd(a,b)$ holds exactly, which is checked by the code and also by hand.

The last row is the one used in the RSA example of Chapter~\ref{ch:crypto}: it shows that $17$ is invertible modulo $\varphi(3233)=3120$, with inverse $-367\equiv 2753\pmod{3120}$.

\section{Modular exponentiation}

Table~\ref{tab:modpow} shows values of \texttt{modpow}. The row $2^{100}\bmod 101$ confirms Fermat's little theorem (Corollary~\ref{cor:fermat}), since $101$ is prime. The rows with $3^{200}\bmod 1000003$ and the RSA numbers illustrate the routine on larger exponents.

\hline

2 & 10 & 1000 & 24\\

Two of these values were also checked by hand. $7^{128}\bmod 13$: since $7^{12}\equiv 1$ and $128\equiv 8\pmod{12}$, we get $7^8\equiv 3$. The RSA rows reproduce the worked example of Section~6.1.3, where decryption returns the original message $65$.

\section{Limits of the checks}

These tests cover small inputs only. The RSA parameters ($n=3233$) are far too small for real use, and the code does no timing analysis at large sizes. Results for cryptographic sizes would need a separate study, which is noted as future work in Chapter~\ref{ch:conclusion}.

\section{Summary}

The routines agree with the theorems on every test case. The worked numerical examples in Chapters~\ref{ch:congruences}--\ref{ch:crypto} are reproduced exactly.
